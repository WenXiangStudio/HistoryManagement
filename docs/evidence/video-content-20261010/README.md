## 内容质量观察

small 模型能保留大部分口播结构，但专有名词、数字和同音词有错误。例如首条视频把“停止使用 OpenAI”误识别成“停职使用 OpenAI”；OCR 同时识别到“所有数学家停止使用 OpenAI”“3个小时平均攻克一个”等画面文字。正式产品必须保留原始 ASR、OCR 和缺口提示，不能静默把转写当作者原文。

本机 CPU llama.cpp + Qwen3-4B-Instruct-2507 Q4_K_M 已能启动，模型约 2.50GB，观察到约 4.6 token/s；首次摘要请求在本机 CPU 上等待较长，且并行长请求触发了客户端超时。摘要结构合同、长文本分段、证据引用检查和缓存键测试已经通过，但**本轮尚未把本地模型摘要质量标为通过**。正式默认策略应先按阶段逐条显示转写/OCR完成，摘要可继续等待或选择云端补充。

## 环境与边界

- 本机 i5-12600K、约32GB内存、Intel UHD770；没有 NVIDIA GPU。faster-whisper 和 PaddleOCR 使用独立 `D:\SDVideoRuntime` Python 3.11 环境，避免系统 Python 和旧工作器。
- 媒体下载使用显式 CDN 主机白名单、大小边界、SHA256 和临时文件；取消、断线和账号变化不会覆盖正式记录。
- PaddleOCR 模型使用本地固定模型目录；首次自动下载未纳入产品流程。
- 本轮没有启动真实云端服务，没有把摘要或模型结果写入正式视频资料库；新增内容状态存储、兴趣标记和兼容快照迁移先在测试库/代码层验证。

## 实施后补充

- 46分钟访谈完整转写：1466个片段，1119.687秒。SenseVoiceSmall在77秒样本上约4.782秒，但遗漏部分外文名词和开头内容，未替换默认small路线。

- 真正交付的本地处理明确保留“摘要待生成”，不是用少量成功字段冒充总结。云端文本/视觉接口已经实现，费用可估时展示，未知时说明；用户尚未配置，未真实外发。
