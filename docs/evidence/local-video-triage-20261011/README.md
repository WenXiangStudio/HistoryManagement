## 实际执行方法

1. 对比APP原片SHA256，核对三个作品对应的既有证据；不读取标题和发布描述来分类。
2. 用FFmpeg解码音频到16kHz双声道，按全音轨RMS选择能量较高的一个声道交给VAD，避免反相混音抵消。另一声道没有独立跑VAD，保留相应覆盖限制。
3. 单独加载faster-whisper包内的Silero VAD v6 ONNX，未加载Whisper转写权重。阈值0.5/结束阈值0.35，最短语音250ms、最短间隔200ms、前后扩展0ms。疑似语音占比是检出区间时长/实际解码音频时长，不是准确率或置信度。
4. 每条在视频流起点至结束前0.25秒之间均匀取8帧，最长边缩至1280像素，保存实际解码时间戳。运行现有CPU PP-OCRv5 mobile文字检测和识别，关闭文档方向、去畸变、文字行方向等其他模型。
5. 使用预先固定的规则保留识别分数至少0.8且至少2个有效字符的文字。平台/账号模式以及持续重复的边缘小字只作疑似覆盖文字过滤，原始框、识别文本、分数和排除原因均保留；本轮没有任何块因这两条覆盖文字规则被排除，排除来自低分或字符不足。未将保留结果宣称为已确认正文。
6. 依据VAD比例和保留OCR帧数生成粗标签。已有像素变化统计随报告保存，但不将变化率映射成画面重要性。没有让Codex根据OCR语义重新命名类型。

所有规则在本轮推理前写入 `rules.json`。三个权重的哈希和依赖版本见[报告](report.json)。来源检查库在初始化时尝试了4次模型站点域名解析，均被离线保护在解析阶段拦截，随后使用显式本地模型目录完成推理；无模型下载或云端推理调用。
