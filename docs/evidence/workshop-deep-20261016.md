# 视频工坊深度处理：APP 0.1.52

用户确认下载与本地分类可用后，要求接入“深度处理”。当前实现已连接豆包录音文件识别极速版及硅基流动 `Qwen/Qwen3.5-122B-A10B`，并已用工坊中已有的真实视频完成转写、画面识别、图文报告生成和界面展示。

## 当前功能

- 选择已下载并完成分类的工坊任务后可点击“深度处理”。不重新下载，不要求标记兴趣，不受旧分类分流规则限制；口播也识别画面，无音轨时仍处理画面。
- 语音采用豆包极速版 `volc.bigasr.auc_turbo`，保留服务返回的逐句起止时间、原文和 Request ID。音轨使用原片时间基准，延迟开始的声音保留前置静音，不移到零点。音频保存到 `E:\AudioDownload\video-workshop\<原片SHA>\doubao-flash-timed-v1\audio.mp3`。
- 画面按约两秒间隔及场景变化抽取，时间来自实际解码帧 PTS。指定 Qwen 模型读取画面文字与可见内容，结果绑定原帧 ID，不由模型填写时间。
- 图文分析与总结也使用此次指定的 Qwen 模型。程序按最多十秒的连续窗口组织语音和画面证据，模型仅填写对应窗口的文字；实际时间、语音段和帧引用由程序回查绑定。跨窗口的整句语音保留原始区间，不按字数伪造分词时间。
- 页面展示整体总结、时间线、每张截图的实际时刻、对应语音原始区间、画面文字、描述及分析，截图读取校验源归属、路径和哈希。切换任务丢弃迟到的旧截图。
- 处理中可取消，失败可继续；成功转写与各批识别保存回执并复用。网络中断且结果未知时保留请求标记，避免重复提交。完成的任务按钮禁用，重新打开报告不调用模型。
- 报告与全部截图加载后记录本次点击至图文实际可用的耗时，与后台及各阶段耗时分别显示。重开历史报告不会重新计算。

- 实际取得 18 张 1280 × 720 帧，时间为 0、2000、4000……34000 ms，各帧分别返回文字、画面描述和识别不确定项。
- 形成四个报告窗口：0–10000、10000–20000、20000–30000、30000–34712 ms。每个窗口的全部帧引用均满足实际时间范围，语音引用均与窗口存在真实时间重叠；不存在跨原片引用或模型虚构时间。
- 全片概括及四段分析、18 张截图和对应语音已实际显示，图片均完整加载。原片、导出音轨、18 帧的 SHA256 另行重算，与回执一致。
- 报告内容准确性仍以用户核对为准。当前验证证明实际提取、保存、显示及时间证据归属；静态采样不能代表逐帧覆盖，模型分析也不是人工准确性验收。

原片仍在 `E:\VideoDownload\video-workshop\2fa21e61-aefd-4451-8140-13235b47acb8\source.mp4`；帧、读取回执与报告在同目录 `workshop-deep-v1`。任务保存在原用户目录 `video-workshop/jobs.json`。

## 真实验证中修复的报告异常

首次运行的豆包转写和六批 Qwen 画面识别均成功。报告在强制 JSON 解码模式下异常生成大量制表空白，触及 8192 输出上限并返回 `finish_reason=length`；程序拒绝保存不完整报告，保留失败回执和全部成功阶段。

针对报告／总览移除强制 JSON 解码参数，仍要求并严格校验完整 JSON；已实测可用的画面 JSON 模式、模型、材料、时间窗口、8192 输出上限和证据哈希不变。显式重试仅重新发一次报告请求，语音与六批画面均命中缓存，报告完整返回并通过结构与引用核对。每次响应保留独立回执，首次异常未被覆盖。

实际调用共一次豆包、六次 Qwen 视觉、两次 Qwen 报告（一次异常、一次成功）。Qwen 本轮累计输入 30,130、输出 15,570，共 45,700 token，含失败请求；费用以服务商为准。结果里的成功阶段累计 usage 含复用的视觉回执，不能再把缓存命中计为新请求。

首次后端尝试 220,352 ms，因报告异常而失败。修复后的报告重试后台 25,144 ms，其中报告 24,875 ms，其他阶段复用。重试点击到报告与全部图像实际可用 77,515 ms，包含当次后台窗口展示等待；不是首次全流程成功耗时，也不作为模型速度排名。
