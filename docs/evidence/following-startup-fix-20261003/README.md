# 重启后首次关注同步修复 · 2026-10-03

用户报告电脑重启后 APP 显示已连接，首次同步十几秒后报 `FOLLOWING_DIALOG_NOT_READY`；点击确认账号登录并重新同步才成功。本轮读取既有真实失败记录，修正页面恢复和状态语义后完成一次真实最小批次，不重启用户电脑。

## 原记录与定位

10 月 2 日 run `following-20261002035038-f417e2d5341688bd` 从 APP 开始至阻断约 11.932 秒，页面阶段 9.8415 秒，零入库；随后手动打开账号页面再同步成功，累计从 100 至 120。

10 月 3 日 run `following-20261003051726-2c2731f9c92080b1` 从 APP 开始至阻断约 12.084 秒，页面阶段 9.2962 秒，零入库；随后手动打开账号页面再同步成功，累计从 120 至 140。

旧 `/commands` 心跳只证明扩展与 APP 相连；内容脚本 ping 也只证明脚本存在。两者均没有证明恢复出来的账号页已正确初始化或关注弹窗可打开。旧失败没有弹窗结构诊断，因此无法仅凭记录断定 React 挂载、页面缓存或隐藏节点哪一个是原始失败的直接根因。代码另有确认缺陷：只要存在任意关注列表节点，即使节点已隐藏，600 ms 重试也会跳过；旧 DOM 根缓存又跳过其他可见根的唯一性检查。

原记录已存入 [reported-failures](artifacts/reported-failures)。

## 修复行为

- Chrome session storage 保存本次浏览器会话已成功采集的 tab ID；浏览器重启或扩展重载自动清空。第一次使用恢复的账号页时程序在后台自动刷新该页面，再采集。后续正常同步不固定刷新。
- 页面保持内部活动后再恢复；先注册导航完成事件再 reload，确保旧文档的 ping 不会被当作新页面就绪。等待页面加载和当前版本内容脚本就绪后才采集。
- 首次打开关注弹窗按真实 DOM 就绪，2 秒未打开或账号页面尚未就绪时，在同一个 APP run 内刷新并重试一次，恢复后的弹窗等待最多 5 秒。登录/安全验证、错账号、资料绑定错误不会进入这个自动重试分支。仍有 APP 整轮截止时限。
- 隐藏列表节点不再抑制点击重试；每次重新核对可见关注根的唯一性，避免 DOM 缓存替代本轮归属验证。
- APP 展示“关注连接器已连接 · 同步时自动检查账号”，同步时显示检查中，真实成功后才显示“本轮账号页面已验证”。APP 重启后账号状态重新未检查，历史耗时与资料保留。
- 自动恢复过程保存在 browser-execution 报告；失败时记录文档 readyState、账号入口可见、列表数及关系页签。APP 起始计时不因恢复或重试重置。
