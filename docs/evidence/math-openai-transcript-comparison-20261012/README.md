# 《数学彻底怒openai了》四种转写模型详细对比

2026-10-12，基于已保存原始输出、计时记录和用户人工反馈做只读核对，没有重新调用模型。作品ID：`7694535682575860393`，作者口罩哥研报60秒，原音轨约77秒。

**实际产生语音转写结果的模型/服务共4种：faster-whisper small、SenseVoiceSmall、qwen3.8-omni-flash、豆包录音文件识别极速版。2种本地、2种云端。** 同一模型的重复运行或一次401失败不新增模型数量。

Qwen3-4B-Instruct-2507和Qwen3.5-4B曾做本地摘要候选，不是这条素材的独立语音转写模型。PaddleOCR读取画面文字，也不计入语音转写。豆包标准版2.0只做过配置准备，没有本条成功转写；不计入第5种。视频口播中提到GPT、Claude，也不是本项目调用记录。

**Whisper small：** 大部分句子结构保留下来了，但存在明显字词替换。`停职`改变动词，`GPD`/`claw的`损伤模型名称，`功课`/`背声`使句意变差。对精确引用作者原话或后续摘要来说，这些错误需要校对，不能直接作为可靠原文。

**SenseVoiceSmall：** 并非所有方面都差于Whisper，它正确识别了“停止”“陶哲轩”“菲尔兹奖”“古法”。主要问题在本条中英混说：Millennium只剩`ium`、GitHub变`giub`、两处Claude消失、英文句只剩`brutal`。输出末尾emoji来自情绪信息后处理，raw保留`<|ANGRY|>`等标签，不能当作作者说出的字词。旧文档笼统称“开头有遗漏”，这次原文件显示“学界彻底怒了AHM人类数学协会庄严呼吁”是保留的；应具体描述上述漏词，不说整段开头都没识别。

**Qwen与豆包：** 两份都经用户独立人工确认本样本100%正确，但文本不逐字相同：空格/标点、Millennium/Claude/Bro大小写、`啊`/`嗯`、`他`/`它`、`自个儿`/`自个`有差异。因此“均人工验收100%”是用户对语音文字正确性的判定，不意味着二者UTF-8字节一致，也不是标准CER/WER测评。两者全文及哈希分别保留，不互相替换或纠错。

## 耗时如何比较

1. **Whisper：26.781秒是worker转写阶段。** 代码从媒体probe/校验、提取WAV前开始计时，包含执行中发生的模型加载和转写，结果JSON落盘在计时后；未单独记录该次模型是否已热加载。它不包含浏览器采集、OCR、摘要、APP最终渲染，不能叫整个APP用时。运行平台是i5-12600K、约32GB内存、无NVIDIA GPU。
2. **SenseVoice：4.782秒来自保存的对照elapsedMs。** 没有APP点击至显示的完整计时，现有对照输出不足以确认计时是否包含初始化，不能拿它与Whisper或豆包直接计算严格的推理速度倍数。
3. **Qwen：原始response.completed中的created_at=1791738151、completed_at=1791738524，服务端间隔373秒（6分13秒）。** 本机report记录启动至超时376.854秒，请求发送至超时375.042秒。不是简单失败无结果：同一SSE中确有完整结果，后续没有重发，从原始流恢复460字符并通过APP追加保存。没有可靠的点击至最终恢复展示总时间，不能把373秒称最终APP全程。
4. **豆包：3.093秒有实际APP点击和原文渲染时间。** 本地准备151ms，请求与完整响应2784ms，结果文件保存6ms，点击至主进程结束2942ms，再到原文显示151ms。请求时间包含网络，不是纯服务端推理时间。后台77秒是音频用量，不是等待时间。

在当前实现和这条样本上，豆包已证明“约3秒完成校验、转写、保存、展示”。Qwen这次大幅更慢，但其调用未限制思考/输出，不能据此宣称Qwen在任何合理配置下都固定需要6分钟。也不把不同计时范围硬算成统一速度榜。

## 费用与用量

| 方案/口径 | 本条记录 | 解释 |
|---|---:|---|
| 两个本地模型 | 云API费用0元 | CPU、内存、电力、模型安装/占用成本未单独计价，不能称完全无成本 |
| Qwen用户转述后台方向 | 0.0456886元，约4.57分 | 输入54,431、输出794，按用户输入0.8/输出2.7元每百万tokens换算 |
| Qwen原始API方向 | 0.1475989元，约14.76分 | 输入794、输出54,431、缓存0；与上一行是同一请求，两行不能相加 |
| 豆包极速版 | 0.017元，1.7分 | 用户后台音频用量77秒及费用换算；不是本次代理独立读取现金扣款 |

按上述已记录金额作算术对比，Qwen分别约为豆包的2.69倍或8.68倍；由于Qwen输入/输出方向未对清，这只能是两种口径对照，不能给出一个已核实账单倍数。此前401失败费用未单独报告，0.017元不视作全部历史请求总账。

Qwen原始API的54,431输出tokens中，思考54,156、可见输出275，约99.49%的输出来自思考；输入794=文字260+音频534。该次只有一次完整音轨请求，图片/摘要/重试均为0。未设置推理强度/输出上限，是当前转写路径的成本控制缺口。不能把数学口播本身或479字符转写说成需要五万多文字tokens，也不能把减去思考费用的算术结果当作低思考方案实测价格。

## 当前结论及尚未实现的部分

**针对这个素材和当前实现，豆包极速版最适合继续作为纯转写产品化的优先方案：** 本样本文字人工验收100%，3.093秒实际APP全程，用户费用换算0.017元，且程序已连续完成处理与显示。两种云端方案质量在本样本都获100%反馈，豆包的当前时间/费用记录更有利。

Whisper有段级时间戳和本地执行优势，但现有small结果有多处错误；SenseVoice本地记录更快，却在关键英文名称处漏词。二者可保留为本地对照，尚无依据替代已验收的云端结果。

Qwen可保留为云端对照；若未来继续优化纯转写，应先核对该服务支持的思考配置、限制预算、修复流式超时与恢复流程，再用授权样本评估。当前没有做这轮优化或新的付费调用。

当前豆包入口是设置页指定样本测试，成功结果在专用speech-tests目录及app_settings中。它没有自动成为全部视频的默认转写器，也没有覆盖视频内容阶段里既有Qwen/Whisper。SenseVoice也没有替换APP默认small。下一步产品化如何接入通用视频任务，仍需按用户后续要求执行。
