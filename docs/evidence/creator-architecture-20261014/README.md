# 资料库底层交互重构：APP 0.1.44

用户反馈此前的局部优化仍在真实点击后频繁卡顿。本轮先用 Windows 辅助功能开启的 Chromium 追踪复现，再按根因重构资料库。

## 根因

0.1.43 在高频区一次挂载 132 张卡片、10,308 个页面元素，Performance 指标统计节点约 22,000（含文本／待回收节点）。真实鼠标点击轨迹记录到 11 个超过 50ms 的长任务，范围 82～191ms；其中辅助功能事件单次最高 175.4ms，点击降权观察窗口内累计布局耗时约 84ms。点击权重、星标或批注都会触发大量节点状态和位置更新。另一个运行问题是日常启动命令残留 `--force-renderer-accessibility`，该参数用于此前自动化验收，进一步放大了点击和滚动开销。

## 重构

- 新增基于 TanStack Virtual 的 `VirtualCreatorGrid`，以当前资料分组为数据源，只挂载滚动视口附近的卡片，焦点卡片会被临时保留；各行按实际测量高度定位，同一列表滚动回收后批注草稿、简介展开、累计作品展开状态按账号及博主身份保留。
- 卡片使用 CSS layout/paint containment，避免单张卡片状态变化让整个资料区重新布局。
- 主进程新增按账号的资料读模型，完整活动装饰、优先级读取和基础字段读取只在数据库版本、账号或北京时间日期变化时执行；数据库变化分别用连接 total_changes 和 data_version 识别本连接及外部连接提交。星标／批注／权重事件直接修补快照。搜索在已有快照本地过滤，主页查询复用快照；冷态单主页查询仍限制读取范围。
- 星标和批注通过 owner + profile 身份的 `creator-annotation` 事件保存，保存中只禁用目标卡片；成功前不改变其他卡片，失败保留草稿。原有星标、批注、账号隔离、数据库事务和飞书变更通知保留。
- 刷新调用使用单活动、单最新待处理快照的队列，连续 data-change、focus 和轮询不会并发读取整库；旧请求完成后只处理最新快照。
- 日常 APP 恢复普通 Chromium 启动，移除 `--force-renderer-accessibility`；验收脚本仍可显式启用该参数。

## 追踪验证

使用同一份 302 位真实资料副本，同一窗口和真实鼠标点击，记录打开分组、勾选、权重、分组切换、恢复自动、星标、批注和点击后的滚动。辅助功能开启的重构前后：

| 指标 | 0.1.43 | 0.1.44 重构 |
| --- | ---: | ---: |
| 高频区挂载卡片 | 132 | **6** |
| 页面元素 | 10,308 | **633** |
| 点击降权观察窗口内累计布局 | 83.8ms | **17.0ms** |
| 同一观察窗口内累计渲染线程任务 | 260.3ms | **80.8ms** |
| 最长辅助功能事件 | 175.4ms | **22.1ms** |
| 完整轨迹中 >50ms 长任务 | 11 次，最高191ms | **1 次，61ms，首次打开分组** |

表格使用前台窗口、辅助功能开启的相同条件，最终构建结果为 `release-force-profile.json`／`release-force-trace.json`，对照为 `before-profile.json`／`before-trace.json`。这些布局／任务指标是点击加之后350ms观察窗口内的累计工作量，并非点击到显示全程延迟；`wallMs`包含人为观察等待，不可作为响应速度。普通启动的最终构建 `release-normal-*` 同样只记录一次61ms首次分组打开长任务；降权观察窗口累计布局14.5ms／渲染线程任务58.6ms，星标切换约10～14ms渲染任务，未出现AX事件。保留并行冒烟遮挡窗口的`candidate-*`无效计时，不参与对比。

首次建立虚拟测量、字体与布局仍有一次初始化峰值，不能宣称任何设备完全没有长帧；结构上已把持续卡顿的全区布局和整区辅助功能更新从点击路径移除。此次没有建立数据库工作线程，首次全库冷读取仍在主进程同步执行，后续读模型复用减少重复读取；不将缓存描述成线程隔离。

完整测试为 77 组 644 项，TypeScript、构建、Windows 打包和 packaged-renderer 冒烟通过。单元与组件回归覆盖读模型失效、单卡标注事件、请求合并、失败草稿保留、旧资料回读、后续外部批注编辑和原有资料库流程。真实打包APP副本额外验证高频132位全部可滚动访问、最多12张卡片挂载，焦点卡片保留、离屏回收、批注草稿恢复、星标重启保存；1120／1464／1680像素分别2／3／4列无行重叠，实际截图核对。结果为`viewport-qa.json`，未使用正式业务库做变更。

日常 APP 已更新为 0.1.44.0，普通启动无调试／辅助功能参数，online／ready；启动和博主资料库 UI 验收通过。更新前后数据库逐表散列一致，302 位博主、95 视频、5 条兴趣、正文报告、128000 额度、星标批注、权重、凭据和账号配置均保留，未改正式权重，也未启动采集或模型任务。
