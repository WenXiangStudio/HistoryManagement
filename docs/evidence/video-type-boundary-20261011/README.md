## APP流程与停止位置

1. 用普通HTTP重定向解析短链接，取得作品ID；按精确ID在已有APP历史快照中查找作者身份、发布时间。只提取机器字段，不向Codex输出视频描述或画面。
2. 复用APP现有 `VideoInformationService.begin(..., captureEvidence=true, explicitTarget)`、关注连接器的归属校验及 `saveVideoEvidence` 保存原片；逐条执行，不使用其他下载器代替APP采集。
3. 调用APP使用的FFprobe程序，检查媒体容器、时长、音视频流及编码。未抽帧、未提取供识别的音频、未运行任何推理。
4. 完成三条的同一非模型采集阶段后，结束审阅任务。当前APP普通处理的后续步骤是本地 `runtime.request('transcribe')`（faster-whisper small，包含VAD），或者云端Omni转写/图片读取。没有调用这些步骤。两种路径都没有已交付的独立非模型语义类型判断阶段。

这次结论针对当前实现：非模型流程能够取得技术结构信息，尚不能据此确定口播主导、画面主导、配乐文字或配乐无文字类型。不是证明任何规则算法永远不能初筛，也不是证明必须完整下载后才能判断。
