# 两次停止原因核对与来源诊断（2026-10-05）

用户要求查清为何连续两轮真实验证停止。本轮核对历史记录、检查判定代码、对同一失败博主做两次限定诊断，并交付持久来源诊断0.7.4。**已确定历史两次停止的本地触发位置；最近一次的具体CDP标识差异仍无法从历史记录恢复，两次诊断没有重现失败，不称来源绑定已经修复。**

第一次错误ACCOUNT_CONTEXT_UNAVAILABLE：旧runner要求预先存在已加载的本人主页，APP扩展在线却不代表页面已经准备。0.7.2已实现自动准备，0.7.3从首位作者主页同时取得账号、计数、原生列表，避免专用账号页。该错误发生在平台请求之前。

最近一次ACCOUNT_NATIVE_NAVIGATION_MISMATCH：0.7.3的owner observer要求Network账号GET的loaderId/frameId等于Page.navigate返回的相应标识；任一字段缺失或不同即拒绝。原失败run仅留下合并错误码，没有保留哪个字段不符、响应状态或处理阶段，因此不能确定是合法文档变化、worker/子页面请求，还是无关来源，也不能归因于未登录或403/429。来源拒绝属于保护行为；它是否误拒绝了合法请求尚缺失败现场证据。

离线测试存在具体不足：原runner fixture的Page.navigate返回空对象，原生账号事件也省略loader/frame；因此集成成功分支没有执行真实的导航一致条件。原owner单元测试已有wrong-navigation拒绝测试，但不足以证明真实网页各种来源都能通过。本轮将集成fixture补成完整导航和账号事件，覆盖账号身份正确/HTTP200/JSON正常却frame不同的整轮停止及记录。
