## 第三批后台计时

准备配置为 20 位新博主，排除两库已保存的全部 20 个主页身份。配置及未启动状态见 [准备状态](../following-client-20261001-batch3/artifacts/preparation.json)。

页面后台计时采用 `performance.now()`；外层桌面命令使用 Stopwatch。计时器不会把当前暂停或准备代码的时间算作采集时间。

1. 页面采集总耗时：页面采集脚本进入时启动，在二十位昵称、简介、主页和头像全部读取并核对完成时停止。包含账号/关注来源核验、列表定位、身份去重、滚动、实际页面读取和头像等待；不含此前页面打开、代码准备、数据库写入及 APP 展示。
2. 平均获取耗时：页面采集总耗时除以实际成功人数；正常完成时分母为 20。失败时保留成功人数及失败状态，不把不足二十位标为完成。
3. 逐作者耗时：在共享列表发现之后，逐条核对并读取作者卡片、滚动至该卡片、等待头像加载的耗时。它不含批次共用的列表发现/去重时间；另记 sharedOverheadMs，因此逐作者耗时总和不能直接当作批次总耗时。
4. 桌面命令耗时：覆盖页面采集、JSON 回传和文件保存。
5. 入库核验耗时：新增记录校验、SQLite 备份、追加保存、回读及本地结果生成，单独记录。

页面计时保存到 `capture.json` 的 `timing`；命令计时保存到 `capture.json.command-timing.json`；追加保存脚本生成 `timing-summary.json` 汇总。逐作者记录包含身份、昵称、开始/结束时间、单调时钟偏移、耗时和成功状态。

准备代码已适配 10/20 位的 DOM 提取与独立追加保存；可见资料报告合同最大值扩展为 20，网络扩展原来固定十位的范围不变。没有启动网站读取、写业务数据库或重新打包/启动 APP。当前 APP 仍是保留修复版，显示原二十位。
