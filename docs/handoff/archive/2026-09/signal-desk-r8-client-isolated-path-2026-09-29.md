## 本次落地

- 桌面端“任务中心”新增单作者单作品隔离入口。它从系统临时目录 `signal-desk-r8/verified-catalog.sqlite` 只读加载已验证 owner 和作者，支持选择一位作者、准备隔离扩展、查看结果与原始报告、结束本轮。没有可信目录时显示缺口，不把旧正式库作者猜作已验证作者。
- 隔离扩展使用固定目录 `signal-desk-r8/client-homepage-extension`，每轮生成新的 loopback 控制器会话。扩展仍由用户从弹窗启动；接收器只向扩展提供选中的一位作者。每次导航前检查控制器存活，结束本轮后停止继续导航。
- 收到经过控制器校验的报告后，客户端再次核对报告合同、run ID、作者 `uid/sec_uid`、作品原生 ID、候选链接、列表证明和详情证明。已验证作品进入该 run 独有的 schema v6 临时 SQLite；作品、来源 hash 和范围受限检查点在同一事务中写入。候选或阻断结果不伪装成已入库作品。正式 `%APPDATA%/Signal Desk/signal-desk.sqlite` 未迁移，也不接收隔离报告。
- v6 草案上增加 `VerifiedFollowingDirectory`：owner 身份绑定、作者双 ID、关系冲突、部分刷新 `stale`、仅完整快照取关，以及“已保存作者作品任务优先，关注刷新独立”的计划。当前只在隔离库和离线测试中运行。每轮单作品隔离任务的关注刷新记录为“未执行”，不能显示为成功。
- 正式任务调度不再在作品入库后自动排评论；评论改为按作品显式创建的独立任务。正式评论连接器与门禁仍未验收，因此产品按钮保持关闭。媒体、ASR/OCR 与云端处理没有纳入隔离链路。

1. 自动关注发现与刷新仍未接入客户端隔离路径。旧 T2 的关注第二页重复不能称作完整快照。要先真实确认 owner 身份和分页推进，随后把独立刷新任务接到临时作者目录；失败只使关系 `stale`，已保存作者同步继续。

## 本机试用方式

运行当前源码或本次 `release-r8-review/win-unpacked` 目录的应用，在“任务中心”选择一位隔离目录中的已验证作者，点击“准备单作品试跑”，打开扩展目录，在 Chrome 扩展管理页加载或重新加载这个固定目录，再从隔离扩展弹窗手动开始。完成后客户端展示作品及两个投影 SHA-256；报告目录包含原始 `pilot-report.json`、`manifest.json` 和 `isolated-sync.sqlite`。出现安全验证或登录阻断时停止，不扩大请求量。
