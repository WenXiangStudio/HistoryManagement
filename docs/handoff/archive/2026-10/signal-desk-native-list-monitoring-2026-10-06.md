# 原生列表监听诊断与取得时机优化（2026-10-06）

用户授权完善监听诊断，再优化原生列表取得时机和读取失败处理。现已部署应用 **0.1.13**、关注连接器 **0.8.2**，从原桌面快捷方式打开，online/ready。日常账号295位及所有旧行、星标、批注和完整快照保留。

## 取得时机和回退

列表监听仍在导航前安装。原生第一页完成加载后立即调用Chrome读取响应内容，并立即投影成作品ID、作者归属、发布时间、置顶和可见性字段；不把完整响应留在APP或持久化日志中等待之后读取。后续原生页仍按需读取，没有新增平台请求或详情请求。

计数稳定后，对未出现的原生请求给予最多600毫秒的到达宽限；出现请求后，整个列表就绪检查以1500毫秒为截止，包含该次检查和取消/验证检查的执行时间。浏览器命令或本地IPC的实际延迟可能令观测耗时略超过计划值。响应读取还有独立2000毫秒截止。等待中持续检查APP会话、周边界、验证码和访问拒绝。

Chrome响应缓存总量从16MiB调整为32MiB，单资源从4MiB调整为8MiB；应用按解码后的UTF-8字节数限制8MiB，每位监听最多24个匹配请求。投影只保留小份作品字段，不保留视频URL、完整响应或无关大字段。此容量是有界的，超过仍记录容量原因并按适用规则停止或回退，不扩大到无限读取。

缺少请求、请求仍在加载、内容读取超时、Chrome缓存已清除/未保留、容量超过上限等情况分别有代码与诊断。总数未变且列表不可复用时，仍按用户确认的启发式做count-unchanged，不额外补发列表GET。总数/最新作品变化、或尚无完整基线时，仍遵循原有完整核验规则，必要的明确列表GET不属于新引入的重试。

HTTP拒绝、验证码、登录要求、调试断开、JSON/来源格式异常等继续停止，不能以“列表不可用”隐藏并跳过。业务自动重试没有增加。每位确认保存后仍先释放读取连接和临时页，再进行作者/批间等待。

## 逐位监听记录

新增独立SQLite表`creator_activity_observations`，按run和作者归属关联。每位从prepared、decision到released或failed保存进度，成功、最新作品未变、仅计数回退和失败都有记录。完成/失败记录拒绝改写，阶段拒绝倒退；记录不能替代登录账号或作品归属证明。监听诊断写入被拒绝时停止本轮，已有资料保留，不继续无记录的采集。

记录包括监听准备、导航、主页面就绪、计数就绪、原生列表决策、保存确认和页面释放时间；匹配请求数、未匹配的作者/方法/游标/子会话分类；HTTP状态、网络/缓存来源、响应加载时间、传输字节、解码字节、内容读取起止和投影条数；浏览器命令错误、文档/子框架协议变化、预期连接释放和读取路径。

读取缓存被淘汰与响应内容未保留保留为BODY_EVICTED/BODY_NOT_RETAINED，不再全部概括成一般读取失败。内容读取、解码、容量检查、JSON解析和投影也区分错误发生位置，避免把JSON/投影失败错误归为Chrome命令失败。诊断数组有上限，不保存原始URL/query、请求头、Cookie、媒体地址、表达式或异常原文。

卡片的count-only分支增加“仅按总数比对：具体原因”。latest-unchanged仍显示“最新作品相同”，完整核验时间不被轻量检查伪造更新。

导出工具：[export-creator-activity-observations.mjs](../../../../scripts/export-creator-activity-observations.mjs)。默认导出当前账号最新资料刷新运行，或指定`--run`，SQLite以只读方式打开；输出含运行状态、每位摘要、完整有界监听记录和失败记录，去除截图；默认写入local-data/activity-observations，拒绝覆盖已有文件。

```powershell

node scripts/export-creator-activity-observations.mjs --run activity-f2a669cbd918a8a506f8cb93
```
