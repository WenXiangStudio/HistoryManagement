## 真实浏览器故障验收

使用已安装 Chrome 的真实 `chrome.debugger`、`tabs`、`scripting`、`storage.local` API。测试副本把抖音 origin 替换为 `http://127.0.0.1:9341`，页面、HTTP 服务和 SQLite 均为本地隔离数据；后端实际调用打包的生产 `CreatorActivityService`。未向抖音发起测试请求，也没有把本地假作者写入日常数据库。

在首位作者的计数执行边界注入故障，配置第二位作者检查停止行为：

| 故障场景 | 浏览器操作 / 注入方式 | 验收结果 |
|---|---|---|
| 调试连接断开 | 实际 detach 后执行真实 CDP 命令 | 原因保留，失败页存在；独立脚本读取 DOM；只读重新附加后取得 JPEG；APP SQLite 收到 frozen → complete |
| 执行期间页面导航 | 真实等待中的 Runtime.evaluate 被本地导航中断 | 原始错误类别保留，标签页仍存在；DOM、截图和两阶段数据库记录保存 |
| APP 诊断写入不可用 | 调试断开，同时本地服务对诊断提交返回 HTTP 503 | APP 未保存诊断，明确显示保存失败；扩展真实 local storage 保存 complete 诊断、DOM 和截图；页面保留 |

三项均停止后续作者，无业务重试。最终与 frozen 的 `capturedAt/errorCode/network/browser` 完全一致。故障页经过 runner finally 后仍存在。本地截图已实际打开确认内容。写入失败使用 HTTP 拒绝注入，并非物理磁盘故障；平台真实失败、其他操作阶段和全部故障类型不因此视为完成实测。

首次验收发现一个真实分类缺陷：Chrome 在导航中断时返回 `Inspected target navigated or closed`，旧分类命中 closed，记为 `TARGET_UNAVAILABLE`。新增 `TARGET_NAVIGATED_OR_CLOSED` 并更新后端白名单，避免声称页面关闭。初次未通过记录保存在 `local-data/failure-acceptance-20261005/initial-classification-failure`，修正后三场景通过。此改动解释的是本地注入结果，**没有证明明石历史失败也是此原因**。

测试缓存仅在其 secUid 明确为 local-* 时清理，原生产扩展恢复后才部署新版。本地故障页保留，测试服务随后停止。证据：[验收汇总](../../../evidence/failure-acceptance-20261005/verification.json)、同目录各场景 JSON/JPEG。可复查脚本位于 `local-data/failure-acceptance-20261005`。
