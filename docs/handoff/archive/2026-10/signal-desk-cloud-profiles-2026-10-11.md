# 云端方案切换与旧模型保留

2026-10-11，用户确认原模型仅支持文本与图像，准备更换厂商和模型，要求设置增加方案切换以避免覆盖旧模型。已实现并交付 APP **0.1.19**，关注连接器仍 **0.8.6**；原桌面快捷方式、日常程序路径与用户资料目录保持。

## 使用

设置 → 云端兼容 API 顶部新增“云端方案”“方案名称”“新建方案”“复制为新方案”。当前保存配置自动成为 **原有方案 · gpt-6.1-sol**，仍为当前生效方案。要填新厂商，先点“新建方案”，为新方案命名，填写地址、接口协议、模型和 API Key，再点“保存设置”。以后用下拉框切换，旧方案的完整配置与密钥可恢复。

每套方案包含文本与可选视觉服务地址、文本协议、模型、上下文和可选单价；本地策略、兴趣标签及账号资料不随云端方案切换。新建方案是空配置，不继承旧密钥；复制方案保留当前云端参数和可用密钥，后续修改独立。空白密钥输入只保留当前方案已有密钥，不会借用另一方案的密钥。方案名称随“保存设置”保存；当前不提供删除方案，最多30套。

有未保存内容时提供“保存并继续 / 放弃修改并继续 / 继续编辑”。后台刷新保留草稿；保存期间新输入的内容继续保留，并中止自动切换。当前方案被其他操作切换时保留旧草稿并禁止错存到另一方案，需明确重载。正在运行内容处理或云端批次时阻止配置修改，避免一批中途换服务。

## 保存与凭据

- `app_settings` 新增 `cloud-profiles` 记录，包含方案列表、当前方案及密钥文件引用；原 `settings` 行继续供运行链路读取当前生效参数。
- 首次迁移保留原配置及 `cloud-api-key.bin` / `vision-api-key.bin`；只新增方案记录，不重写既有加密文件。
- 新密钥通过 Windows safeStorage 加密为独立 UUID 文件，明文不进 SQLite、不回传设置界面。
- 设置验证和活动方案变化在 SQLite 事务内完成；密钥更新使用新文件引用。失败时回滚参数和引用，不能覆盖旧方案的密钥；安全存储中途失败可能留下无引用的加密文件，不自动删除凭据。
- 旧云端分析和视频内容处理均通过当前方案取得正确的文本/视觉密钥；不以一个固定密钥文件承担所有厂商。
- `scripts/read-active-cloud-config.cjs` 已供两个既有云端验证脚本使用：根据当前方案读取密钥，缺密钥就拒绝，绝不回退到旧厂商密钥。后续更换模型试验需使用新的证据输出目录，保留10月11日盐选财经试验原始结果。
