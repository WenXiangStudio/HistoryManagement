# 视频工坊：当前规划与界面设计

更新日期：2026-10-16。以用户最新安排为准：先更新规划文档，再重做界面；第一步仅支持抖音视频链接。

本规范替代此前工坊的规划与设计。“只收录感兴趣作品、只展示基础信息和截图”不再是新工坊的主流程；历史资料保留在独立入口中，不删除既有作品、兴趣、博主、星标、批注或报告。

当前 APP 0.1.52 已接通下载与本地分类，以及用户点击后的深度处理：使用豆包极速版取得带分句时间的转写，使用 `Qwen/Qwen3.5-122B-A10B` 读取采样画面并综合生成时间对齐图文报告。支持实际进度、失败原因、取消、成功阶段复用与重启恢复，不使用模拟进度或样例报告冒充处理结果。

## 用户流程

### 1. 输入抖音视频地址，点击“处理”

工坊首页提供单条视频地址输入框，支持手动输入、粘贴抖音完整视频链接或带短链接的分享文案。首版接受 `www.douyin.com/video/{作品ID}` 和 `v.douyin.com/{短链标识}`，校验平台和链接类型；短链接最终身份以实际解析结果为准，不把短链本身当作视频 ID。

用户点击“处理”后，程序应连续完成地址解析、视频下载、源文件校验和本地视频分类，界面显示该视频的基础信息与实际分类结果。首版不包含其他平台，也不支持直播、主页或合集批量处理。

此入口不依赖博主资料库、发布日期查找、感兴趣标记或收藏。分类只承担内容类型判断，帮助用户了解素材；本步不调用云端转写、画面识别或报告生成。分类不再决定用户能否继续深度处理。

新下载视频保存到 `E:\VideoDownload`；下载或导出的音频保存到 `E:\AudioDownload`。按视频身份、文件哈希及处理版本核验复用，不覆盖其他素材；E 盘路径不可用时明确显示原因，不能静默写回项目盘。

### 2. 点击“深度处理”

视频下载与本地分类完成后，用户点击“深度处理”，才启动语音转写、画面识别与图文综合报告。

| 处理内容 | 默认服务或模型 |
| --- | --- |
| 云端语音识别 | 豆包录音文件识别极速版，资源 `volc.bigasr.auc_turbo` |
| 云端画面识别 | `Qwen/Qwen3.5-122B-A10B` |

读取对应已保存模型与凭据，不覆盖用户其他方案，不为任务修改全局当前云端模型。缺少配置时提示具体问题，不静默改用旧 Qwen3.5-4B 或其他模型。

报告综合分析同样使用本次已指定的 Qwen 模型，输入有时间依据的语音片段和画面读取结果，不另行隐式切换 GLM 或其他总结模型。单次成功转写、各批次画面和报告请求均保存源哈希及回执；失败重试优先复用已完成阶段，网络中断且结果未知时保留请求标记，避免重复提交。

深度处理需要同时考虑语音与画面：口播类也识别画面，纯画面类也可以进入深度处理；确实无音轨或无语音时如实记录，仍分析实际画面。不能沿用“口播只转写、纯画面只人工观看”的旧工坊设计。

保留每个成功阶段及源文件身份，失败后可以继续。只有模型、文件和处理规则一致且校验通过的结果才能复用，旧无时间戳全文不能直接充当已经对齐的图文证据。

### 3. 输出时间对齐的图文分析与总结报告

成品是一份结合视频语音、画面文字和画面信息的分析总结报告，包括全片概括、按时间顺序的图文分析、关键结论与证据引用。不能只将完整转写和截图列表并排展示就认定完成图文融合。

每个分析段落显示原视频时间区间、对应截图及实际帧时间、该段语音转写、画面文字或描述，以及基于这些材料的分析与总结。整体结论也应追溯到具体语音段和视频帧。后续支持点击时间、语音或配图定位原视频，便于核对。

当前实现由程序划定不超过十秒的连续报告窗口，分句按真实起止时间与窗口重叠关系归属，画面按真实帧时间归属。模型仅填入对应窗口 ID 的分析和总结，窗口时间及语音／帧引用由程序绑定。跨窗口的完整语音句保留原始起止时间，不从整句文本猜测切词时间；每张配图仍单独标示其实际时间点。

未完成深度处理时显示空状态，不填入编造的内容、时间、图片或成功状态。

## 时间精确对准的要求

同一份原视频的播放时间轴是唯一时间基准，内部统一使用毫秒，并保存原片哈希。音轨抽取、分块及抽帧必须处理音视频起始偏移、分段偏移和变帧率，不能因重编码或裁剪丢失与原视频的对应关系。

- 语音保留服务返回的分句或词级起止时间和原文，不从无时间戳全文猜测、按字数均分或由模型编造时间。
- 图片保留实际解码帧的显示时间戳（PTS），不把计划抽帧时刻或“第几帧乘采样间隔”直接当成真实时间。
- 语音片段和视频帧有不可变证据 ID。报告引用 ID，由程序回查原始时间和素材，拒绝不存在、跨文件或错段的引用。
- 单张图片是时点证据，不自动表示整段持续内容。区间内发生画面切换时细分或展示多帧；没有证据时不能认为同一文字一直显示。
- 某段缺少对应画面时补取实际帧或标明缺失，不能强配远处图片。抽样遗漏、时间缺失和识别失败均不能显示为已精确对齐。

时间归属正确与模型内容识别准确分别验收，不能用时间字段齐全替代真实语音、画面及分析内容的核对。

## 界面结构与本轮边界

主导航使用“视频工坊”，进入后默认“新建处理”，按顺序显示：

1. 抖音链接输入区、“处理”按钮，以及本地下载／分类步骤。
2. “深度处理”区域，明确展示默认语音和画面模型。
3. 图文报告区域，预留全片总结、时间轴与每段画面／语音／文字／分析的位置。

原有收录作品可在“历史资料”中查看，既有跳转可定位该资料，不将其自动标为新流程任务或已经对齐的报告。

有效链接在任务记录读取完成且没有运行任务时启用“处理”。点击后显示真实解析、下载与本地分类状态，任务结果始终标明本次提交的链接、作品编号和保存文件，不随输入框中的后续编辑改变归属。公开下载受限时通过已连接 Chrome 的对应作品页面取得媒体，精确核验作品编号后下载，不导出浏览器 Cookie。任务记录与原资料库独立保存，不修改旧视频或博主。

下载与本地分类完成后启用“深度处理”，仅处理用户选中的已保存任务，不使用输入框中后来编辑的其他链接。界面展示准备、转写、画面识别、报告生成、完成／失败／取消的实际状态；失败可直接重试深度阶段，原片与分类保持不变。报告引用的截图经源归属、时间和文件哈希校验后读取，切换任务时丢弃迟到的旧截图。报告与全部引用图片可用后记录本次点击至图文可用的耗时，重新打开历史报告不重新计算该时长。

不得连接旧的按兴趣分流接口来冒充新流程，也不得在进入页面、保存配置或输入链接时自动下载或发起云端调用。
