# 作品发布历史与公开可见性讨论稿（2026-10-04）

后续用户指定公开作品总数直接取主页“作品”计数，最新见[前端计数](../handoff/archive/2026-10/signal-desk-frontend-work-count-2026-10-04.md)。下文“当前行为”为此前时点；发布历史累计及删除状态仍是讨论方案，本周主统计未改为历史发布累计。

## 当前行为与问题

公开作品总数来自平台profile，周数量和最新发布时间从一次可信的作者公开作品列表计算。最新完整周快照优先，失败时保留已有可信资料。历史capture及snapshot累计保留，但卡片没有把多个快照里的作品合并为发布历史。

如果一个作品周一发布，周三删除/私密，下一次完整读取可能发现作品总数下降、本周更新减少、最近发布时间回退；如果这是该周唯一作品，作者可能从中区变为下区。作为“目前公开可见”的统计，这些变化合理；作为“本周曾发布”的统计，会误导。删除、设为私密、登录状态变化、作者主页返回缺页等情况也不能用一次列表缺失简单区分。

## 建议口径

| 指标/功能 | 口径 | 原作品随后不可见 |
| --- | --- | --- |
| 卡片作品总数 | 平台当前公开作品总数，附检查时间 | 按可信新值变化，允许减少 |
| 本周更新、最近更新、三区归属 | 在固定日历周内已验证、已记录的发布事实；按原生作品ID去重 | 发布记录继续存在，不因不可见回退 |
| 当前周内可见作品数 | 最新完整检查仍公开可见的周内作品 | 可减少，可在提示中单独展示 |
| 收件箱、收藏、批注、已分析记录 | 本地记录及其采集时证据 | 保留，增加来源公开不可见提示 |
| 点赞/评论/收藏、评论数量 | 带观察时间的快照 | 取不到时未知，历史值不归零 |
| 摘要、ASR/OCR、评论分析、博主画像 | 引用具体采集快照/证据版本的历史分析 | 保留来源时点；重新分析另生成版本，避免混入无法核实的新状态 |
| 导出 | 同时携带发布时间、观察时间、统计口径和可见状态 | 能区分“曾记录”和“当前公开可见” |

建议保留现有“本周更新”主文案，但用说明明确为“本周已记录发布”；如发生变化可提示“本周已记录1条，当前公开可见0条”。平台公开总数与历史发布数分别表示不同问题，不能通过总数净增减倒推新增或删除：同一天新增1条并删除1条，净变化为0。

例如周一首次看到作品A，周三A不再公开：本周发布记录仍1，最近发布仍周一，作者周三仍归中区；实时公开作品总数下降，A公开可见性单独待复核。作品重现且原生ID相同，不新增发布记录；重新上传且ID不同，视为新的平台作品，并使用其真实发布时间。

## 数据与核验机制

发布记录需要原生作品ID、平台、账号/作者归属、发布时间、首次和最近观察时间以及来源快照引用。以账号隔离资料，以作者和原生作品身份去重。不能用昵称、标题或总数变化识别作品。已有经过归属与发布时间校验的capture可以只读回填这些事实；没有观察到的内容不能补造。

可见性和发布事实独立存放，历史观察不删除。检查失败、账号不匹配、风控、分页未覆盖对应日期范围时，只记检查失败或未知，不改变作品可见状态。连续完整且可比的检查未出现可进入“待复核/疑似不可见”；需要公开详情或平台明确证据才能确认公开不可见。有明确删除证据才标“已删除”，否则保留“公开不可见，原因未知”，不能把私密和删除混为同一结论。

后续验证先按AGENTS.md以最小真实读取证明公开不可见证据可取得，再接入状态入库与展示。自动复核由APP控制限量、取消和重试，不能依赖代理逐条发命令，不能用本方案提前宣称正式作品详情或评论采集已验收。

如果作品在两次采集之间发布又删除，而产品从未看到，就不能知道它曾存在。当前刷新是手动触发，不能宣称捕获全部发布；即使以后定时检查，也需使用“已记录”口径并展示最后检查时间与覆盖状态。
