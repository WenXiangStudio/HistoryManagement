# 视频基础信息采集：首个可用步骤

本文保留0.1.14/0.1.15首步能力与验收范围。0.1.16新增日期范围、多作品与本地材料处理，见[当前视频内容处理说明](video-content-processing.md)。

截至 2026-10-10，APP **0.1.15**、关注连接器 **0.8.5**。采集链路在 0.1.14 通过单条真实样本验证；0.1.15 将展示提升为平级“视频信息”导航页，汇总当前账号已有视频。它是独立的有限入口；完整作品/评论任务仍保持 `STRUCTURED_SYNC_AVAILABLE=false`。

## 使用方式与范围

直接进入左侧 **视频信息** 可查看当前账号全部已保存视频；**博主资料库 → 博主卡片“视频信息”** 跳转到同一页面并自动筛选该博主。选择博主后可点击“采集最近一条视频”。详情中的“查看博主资料”返回并定位其资料库分组。

- “最近”指本地最近一次可信主页状态快照中，发布时间最新的普通公开视频；不是全站实时发现，也不是遍历所有历史作品。需先有原生作者身份与可信作品记录；异常博主先完成“核验并补齐”。
- 每次只读取一位博主的一条已知视频。目标若不在当前主页首屏列表，报告需要刷新主页状态，不自动翻页、改选视频或逐作品打开详情。
- 保存发布描述全文、由描述首个非空行派生的显示标题、发布时间、时长、赞/评/藏/分享精确计数、原生作品 ID 与作者 UID/secUID、采集时间。
- 未提供的字段保留 `null`，展示“未取得”；真实 0 与缺失分开。显示标题最多 120 字，完整发布描述不按显示标题截断。
- 暂只接受经过公开状态检查的 `aweme_type=0` 视频。图文、临时作品、不可确认公开状态的结果拒绝写入。
- 此步不采集评论正文、不下载媒体、不启动 ASR/OCR/总结或定时监控，也不写入尚未定稿的今日收件箱。

## 读取与验证

浏览器执行入口为 [video-information-runner.js](../../browser-connector/following-extension/video-information-runner.js)，字段投影为 [video-information-core.js](../../browser-connector/following-extension/video-information-core.js)。

1. 从当前账号的累计博主资料库取得稳定身份，并从可信 `creator_activity_snapshots` 选择目标作品；不重新获取关注清单。
2. 打开一个本任务创建的作者主页，先监听再导航，优先利用页面自然收到的第一页作品列表 JSON。原有活动观察器增加可选投影函数，默认活动采集仍只保留原字段。
3. 核验当前登录账号；优先观察原生账号响应，没有原生账号请求时才发起一次页面内账号 GET。拒绝、验证或错账号不能视为“未观察到”。
4. 只有未观察到原生作品列表请求时，才允许一次页面上下文第一页 GET。已观察到 HTTP 拒绝、异常响应、超时或内容不匹配时停止，不补发、不翻页。
5. 投影只留下目标作品。核对原生作品 ID、作者 UID/secUID、发布时间与本地快照，公开状态通过后由主进程按严格 schema 再验一次，并核对 owner、run、来源和请求计数。
6. 成功保存后解绑调试会话并关闭本任务页面。失败保留现场；取消或超时后的晚到结果不能写作品记录。

扩展主动作品 GET 最多 1、账号核验 GET 最多 1；这不是整个页面请求总量。页面自然加载也会请求接口和资源，审计另记已观察网络总请求、平台 API GET、账号和列表请求数。单页面验证不能证明长期批量封控概率。

## 保存与关联

[VideoInformationService](../../src/main/videoInformationService.ts)管理单次状态和时间界限，[VideoInformationStore](../../src/main/videoInformationStore.ts)在现有 `following-directory.sqlite` 中增加三张独立表：

| 表 | 职责 |
|---|---|
| `video_information_runs` | 按账号保存任务状态；重启时将未完成任务标记为中断 |
| `video_information_snapshots` | 按 run 保留不可变字段与来源快照 |
| `creator_video_information` | 以 `(owner_sec_uid, work_id)` 唯一定位当前记录，关联 `creator_sec_uid` 与 `author_uid` |

重复采集同视频更新当前快照，保留首次收录时间及历史快照。更旧的结果不能覆盖新结果；同一账号中的相同作品 ID 若发生作者身份冲突则拒绝。不同账号分别查询和保存；界面切换账号后，旧账号晚到结果不会展示到新账号。

作品通过当前账号与博主主页身份关联，不靠昵称或某批次列表位置。已有博主、星标、批注、自定义字段和主页观察不被更新或删除。此次没有迁移旧收件箱 `works` 表，也没有启用隔离 v6 的旧任务路径。

## 展示与计时

[VideoInformationPage](../../src/renderer/src/VideoInformationPage.tsx)集中展示当前账号记录，使用左侧作品列表、右侧详情阅读的布局。顶部提供总视频数、博主数、最近采集时间和当前采集对象；支持全文/作者搜索、博主筛选、最新发布/最新收录/点赞排序、复制文案。长列表分批显示，左右独立滚动，详情保留完整文案和采集时间。页面视觉样例见[导航页验收](../evidence/video-library-20261010/README.md)。

切换导航保留筛选及选中作品，隐藏页面暂停副作用和轮询；账号切换重置该页状态，旧账号响应不能写入新账号视图。只在采集运行时短周期查询本机状态；查看、搜索、筛选和排序不请求平台。点击采集后，程序连续完成浏览器读取、主进程校验、保存及页面刷新；代理验证脚本不是产品工作流程。

详情展示全文、精确数字、发布时间（北京时间）、时长和统计采集时间，并区分平台评论数与未采集的评论正文，以及发布文案与口播转写。

- `acquisitionMs`：扩展本轮读取阶段耗时。
- `savedTotalMs`：主进程收到开始动作至记录及报告保存。
- `displayedTotalMs`：主进程收到开始动作至本次选中视频详情渲染回执。原有作者身份已在资料库，页面使用姓名标记，不在此步重新采集头像。
- 验证脚本另记操作发起到观察到结果的耗时，包含脚本轮询间隔；不能当作更精确的产品计时。
- Windows 遮挡/最小化可能延迟渲染回执，此时总时长包含等待，不能用保存阶段数字替代。最终计时验证使用临时 `CalculateNativeWinOcclusion` 禁用参数，交付启动不带该参数。

## 验证与后续

运行 `npm run test:video-information` 可验证字段、账号/作者归属、缺失值、拒绝与取消、一次 GET 分支、去重、历史保留和面板隔离。原生观察器回归、应用测试、类型检查、打包和 renderer 冒烟另行完成。

本次真实样本和限制见[验收记录](../evidence/video-information-20261010/README.md)。仅一条公开视频真实通过；受控 GET、私密/图文、外账号和错误分支由离线测试覆盖，不据此宣称更多博主或全部作品类型已稳定。

后续仍按最小样本逐步扩展覆盖；评论、下载、转写和总结分别推进。今日收件箱的时间口径及具体联动规则继续待讨论。
