# 博主数据库接入飞书多维表格

已完成真实飞书连接、295位全库同步、重复同步和自动同步，并部署到日常 APP。首次连接仍先验证一位真实博主，再启用全库与自动同步；当前账号已配置并开启自动同步。

## 人工准备

1. 登录 [飞书开放平台](https://open.feishu.cn/app)，创建企业自建应用，例如“Signal Desk 博主同步”。
2. 在应用权限管理开通 `bitable:app`（查看、评论、编辑和管理多维表格），创建版本并发布；组织要求管理员审批时，由管理员批准。
3. 在飞书客户端新建独立多维表格和一张空白数据表。在文档菜单的“添加文档应用”或协作者授权入口添加该应用，授予编辑权限。应用 API 权限与具体表格的文档授权需要同时具备。
4. 打开具体数据表，复制包含 `/base/` 与 `?table=tbl…` 的完整链接。当前未接入 `/wiki/` 知识库链接。
5. 在 Signal Desk → 博主数据库 → 连接飞书中填写 App ID、App Secret、链接并保存。Secret 直接填入本机 APP，不需要发送到聊天。
6. 选择一位博主，点击“写入一位并核验”。成功时 APP 显示新增/更新结果、读回一致的字段数和时间。打开飞书确认样本对应正确。
7. 点击“同步全部博主”同步当前账号全库，或勾选“自动同步”。自动同步在 APP 运行时生效，采集入库、星标/批注、自定义列保存后约5秒合并触发；每分钟补查是否有未同步的本机变化，重新启动后补同步。

已安装的飞书客户端用于登录、创建表格、授权和查看数据；持续程序同步使用开放 API 的应用凭据。客户端登录不会自动授予另一程序表格读写权限。

## 字段和归属

| APP 数据 | 飞书列类型与处理 |
|---|---|
| 博主昵称 | 文本 |
| 上次更新日期 | 日期，按北京时间当天零点写毫秒时间戳 |
| 作品数 | 数字，0 和未知空值分别保存 |
| 间隔天数 | 与 APP 一致的“X天Y小时”文本；记录不足为空 |
| 活跃情况 | 中文文本：高频、中频、低频、极低频、待确认；与APP当前生效等级一致 |
| 自定义文本/整数/日期列 | 对应文本/数字/日期类型 |
| 主页 | 超链接 |
| 星标、批注 | 复选框、文本 |
| 资料账号、博主标识、同步标识 | 文本，用于归属与去重 |

同步字段带“APP ·”前缀，初次使用 APP 当前表头。保存飞书 field ID 后，任意一端改表头不会改变字段身份。移除本机自定义列不会删除飞书历史列及内容；飞书独立添加的业务列保持原值。当前同步是 APP → 飞书，APP 管理列的飞书编辑会在下次验证该博主时被本机值更新，不回传 APP。

记录键为 `douyin:<ownerSecUid>:<creatorSecUid>`；匹配同键后，还核对账号、博主标识和主页链接。同主页记录的键缺失/不一致、重复键、远端字段类型冲突、已映射列被删除均停止并提示处理。不调用记录/字段删除 API，不因空结果删博主，不修改本机资料、星标、批注。

## 实现与失败行为

- 凭据和按账号的字段映射由 Electron `safeStorage` 加密，文件位于 userData/credentials/feishu-<账号哈希>.bin。IPC 返回的状态不含 Secret；访问 token 只存在主进程内存。
- 请求固定发送到 `https://open.feishu.cn/open-apis/`，拒绝重定向，单请求超时20秒。输入的表格 URL 只解析 token/table ID，不成为凭据发送地址。错误只显示 HTTP 状态或飞书错误码，不显示可能回显凭据的响应体。
- 字段列表每页100、记录列表每页500，完整读完全部分页再写记录。字段新增顺序执行并间隔150毫秒；字段 ID 逐项持久化，部分失败后可续做。
- 全库按每批最多100条新增/更新，仅写入有差异的记录，然后重新读取全部远端记录逐项核验。无变化仍核验，不重复写入；空或部分本机结果不触发任何远端删除。全库不受界面筛选影响。
- 全局串行验证；进行中不能改连接配置。每次远端写入前检查本机当前账号，避免切换账号后混写。
- 新建使用 API 的 UUID client_token，全库待确认批次的 token 保存在加密配置中。失败后先完整读取远端记录再决定重试；开启自动同步时按1、2、4、最多5分钟退避，手动重试可立即执行。已可见的成功写入不会再次新增。
- 自动同步对本机投影做内容哈希，无变化不发请求；飞书单独编辑不会触发回传，手动全库同步可重新核对远端变化。每个 userData 只启动一个 APP 实例，避免同库两个写入进程。同步运行状态与结果保存在本机，异常中断显示可重试。
- 写入后 GET 对应 record_id，核对默认字段、自定义字段、归属、主页、星标、批注，全部一致才保存成功凭据。读回失败可能已留下实际记录，界面明确说明并支持重试。
- 单条“写入与核验耗时”、全库“同步处理耗时”从主进程任务开始至读回完成。界面另显示手动“点击到结果可用”的全程耗时；这些均为飞书同步指标，不替代资料采集到头像可用的全程耗时。
