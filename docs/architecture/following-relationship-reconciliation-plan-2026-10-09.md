# 最新关注关系与“取关”分区方案

日期：2026-10-09。状态：用户明确要求本轮先确定规则与方案，暂不修改产品代码。本文件是待实施设计，不是当前能力说明。

用户提出：已有 295 位关注博主，之后若取关 2 位，再同步关注清单，应显示最新 293 位关注；原 2 位进入独立“取关”分区，原资料继续保存。这补充了“累计博主资料库”的关系变化处理，不改变不得删除历史资料、星标和批注的原则。

**数据语义**

长期档案与当前关注关系分别保存。档案继续以资料账号 + 博主主页身份为键，保留原记录 ID、资料、星标、批注、自定义值、手动权重、作品和历史证据。“取关”是关系状态与界面分区变化，不搬移或删除档案。

显示至少区分“当前关注”“取关”“累计收录”。295 → 293 的可靠完整同步后显示 293 / 2 / 295。若同时新关注 3 位、取关 2 位，则应按身份集合得到 296 / 2 / 298；不能用总数差判断取关对象。若重新关注取关区的 1 位，则复用旧档案，恢复当前关注及对应分组，星标批注不变。

“取关核验时间”只能表示 APP 最近确认其不在当前关注列表中的时间，不能称为用户实际点击取关的时间。没有额外关系证据时，文案应解释为“最近完整关注清单中已不再关注”；账号停用、平台可见性变化等不能被臆断为用户主动操作。

**建议的判定规则**

| 本轮结果 | 关系处理 |
|---|---|
| 同一账号、连续分页至明确末尾，字段和身份验收通过，完整性依据一致 | 提交新的完整关系快照；对比前后身份集合，更新关注及取关状态 |
| 仅取得前几页、取消、超时、登录失效、验证码、拒绝、游标异常 | 保存已确认取得的档案和观察；不将未出现者移入取关区；保留上次可靠关系快照并显示未完成 |
| 有效非空结果，但独立计数与去重身份数不符，或同步中关系变化导致边界不稳定 | 标为关系待确认，不将缺失者批量判取关；不自动补发业务请求 |
| 空响应、无法解析或仅有未经核对的空数组 | 保留原关系；不能据此将全部移入取关 |
| 完整空清单，且有一致、可信的“关注数为 0”证据 | 更新当前关注为 0，全部既有当前关注档案进入取关区；仍不删除任何历史资料 |
| 取关作者重新出现于可靠完整清单 | 恢复原档案当前关注状态，移出取关区，继续按已有频率规则分组 |
| 只有作者基础资料/主页状态更新 | 不改变关注关系；“读取过主页”不证明已经重新关注 |

分页完成并不天然等于平台数据绝对完整。应尽量从已有账号核验响应或已加载页面复用关注总数，与完整分页去重数相互印证，不为每个博主增加主页访问。若某条接口确实不提供独立总数，需要先最小样本验证可用完整性证据，不能直接把 `has_more=false` 当作所有情况下足够的缺失判定。全量集合的计数吻合也不能排除遍历期间关注关系变化相互抵消；出现来源或差异异常时保留待确认。

当前流程允许跨中断续跑并累计档案。对关系快照需要更严格：跨长时间中断或不能证明同一稳定遍历的拼接结果，不用于判定其他作者取关。续跑仍可补齐资料，关系状态等待下一次从头完成的可靠清单。具体有效时长不在无实测证据时随意设一个“安全数字”。

**界面和刷新范围**

- 资料库新增独立“取关”入口，展示人数、昵称、头像、最后一次关注关系核验时间及原星标/批注。操作仅影响本地展示，不调用抖音取关接口。
- 当前关注作者继续进入高频/中频/低频/极低频或异常区；取关作者以取关区为展示优先级，已有作品异常标记仍保留。
- 取关作者默认退出常规分组更新、全量主页更新及未来后台监控。仍可查看历史；若保留手动读取入口，应由用户明确选择该作者执行。
- 重新关注后，异常未解决者回异常区；其余按原有有效证据及手动权重规则归组，不伪造新主页状态。
- 同步过程中“本轮已读取 N 位”与“最近完整核验关注 M 位”分开。不能把累计档案数当最新关注数，也不能把本轮尚未读完的数量当最新全量。
- 博主数据库保留全部档案，可按关注关系筛选；增加独立关系字段时不占用或改写既有五个自动字段的语义。飞书仍不删除取关记录，未来以新增关系字段同步状态，保持旧记录键和自定义列。

**建议实现边界**

当前 `FollowingDirectoryStore.list()` 在目录投影中将 `isFollowing` 固定为 true，`following_list_plans/pages` 保存分页与完成信息，但没有独立的历史关注关系状态。因此只增加一个 UI 过滤器还不够。

拟增加账号级关系快照及关系状态投影，至少保存 ownerSecUid、creatorSecUid、状态、关系核验时间、来源完整 run、最近出现 run；原始分页与完整性依据继续保留。收到每页仍按原路径累计档案，在关系验收通过的终页事务中原子提交关系快照；事务失败不得出现“列表变了但数量没变”。新旧快照的差集必须基于身份，不使用昵称。

接入点为 `FollowingPlanStore.page()` 的完整清单验收、`FollowingDirectoryStore.list()` 的关系投影、`FollowingSyncService` 的统计与刷新目标选择，以及资料库/数据库/飞书的展示投影。基础资料补全使用自己的观察路径，不触发关注关系对账。现有计时继续包含保存与头像可用，关系计算阶段如需单列，不能代替全程指标。

旧库首次升级不追溯把历史未出现作者批量标为取关。原档案全部保留，关系可显示待重新核验，首次满足新规则的完整同步后再建立当前关系。该迁移行为与最终显示文案应在实现时一并验收。

**后续验收场景**

至少覆盖：295→293、增减同时发生且总数不变、重新关注、空列表与错误空响应、部分结果、取消后续跑、计数不符、分页期间关系变化、账号切换、UID/主页冲突、重启恢复、事务失败；验证原记录 ID/星标/批注/自定义值/历史证据不变，取关作者退出常规更新、飞书不删除记录。先用隔离合成资料验证逻辑，再在用户正常发生的关系变化上最小真实核验，不为了测试主动取关任何账号。
