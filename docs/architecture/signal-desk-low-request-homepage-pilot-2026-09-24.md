# Signal Desk 低请求量作者主页试跑

> 2026-09-24。隔离试跑实现说明。正式结构化同步门仍为 `false`；正式 SQLite 和既有 R8 报告均不改写。

## 当前执行路径

1. 输入来自此前已独立验证的隔离作者目录，包含 owner、作者 `uid`、`sec_uid`、主页 URL 与关注状态；旧数据或身份冲突作者不会进入候选。
2. 新扩展加载后**不会自动运行**。操作者在弹窗选择一位作者并启动。若没有已打开的抖音页面，扩展会在同一测试标签页打开抖音首页作一次前置检查；若显示验证或登录提示，立即结束并写 `blocked` 报告。已有抖音页面只读检查，不额外导航首页。
3. 仅导航这位作者主页。主页中可见的 `/video/<aweme_id>` 或 `/note/<aweme_id>` 链接先作为候选；候选最多 6 个，不会仅凭卡片写成正式作品。若页面自然发出的作者作品列表响应中，同一原生作品 ID 的 `author.uid`、`author.sec_uid` 与目录身份均匹配，才选择首个已证明候选。
4. 最多再导航这一个作品页。只有页面自然发出的详情响应同时匹配作品 `aweme_id` 和双作者 ID，才在隔离报告中标 `verified`。缺少自然响应则标 `candidate-only`，不会为了补齐证据主动重放接口。
5. 单轮最多 3 次页面导航（需要首页前置检查时为首页、作者主页、作品页；已有正常抖音页面时最多 2 次）、0 次主动接口请求；评论、回复、媒体下载、ASR/OCR 和云调用均不执行。`NetworkObserver` 只观察浏览器页面自身请求。报告只保存白名单投影与来源 hash，不保存 Cookie、签名或原始响应。
6. 已验证或仅有候选时保留测试页供人工对照；因验证、登录或执行异常阻断时关闭测试页。弹窗显示结果、作品 ID 或候选数、报告目录。首次真实试跑暴露了原实现总在清理阶段关闭页面的问题，此处已修正；首次 run 的报告不改写。

## 与原 T2 的区别

此前隔离 T2 默认在同一轮主动请求关注列表及翻页、多个作者作品列表、六个作品详情、一级评论和回复，最高并发 3。真实运行显示关注第二页重复，六作品仅部分成功，之后浏览器出现安全验证。本试跑把关注目录建设和作品页处理分离，先验证从已保存作者主页取得一件作品的最小闭环。原 T2 仍为失败证据，不因新试跑结果自动升级。

主页卡片路线参考 `ai-boshu-crawler` 固定提交 `57ad263c0be8cf234bcadbc5c07dedc72304d182` 的行为思路，没有复制其代码。该项目主流程的可见作品卡片与页面元数据足以服务自身日更下载，却不能单独满足 Signal Desk 的作者归属硬门槛，因此这里保留自然结构化响应的双 ID 核对。评论作为独立后续任务设计，不在本试跑中启动。

## 离线验收与真实门槛

- [`r8-homepage-pilot-core.js`](../../browser-connector/extension/r8-homepage-pilot-core.js) 的离线测试覆盖：正常双 ID 绑定、页面安全提示、仅可见卡片、错误作者、错误详情。
- [`homepage-pilot-controller.mjs`](../../poc/r8/homepage-pilot-controller.mjs) 只接收已验证作者的单轮有界报告，拒绝主动请求计数、错误作者和敏感字段。
- [`start-r8-homepage-pilot.ps1`](../../scripts/start-r8-homepage-pilot.ps1) 只创建系统临时目录、只读打开作者目录、保持生产能力门关闭。真实试跑需要操作者确认 Chrome 当前没有安全验证，并手动加载新扩展、选择作者、点击开始。
- 实际页面是否自然提供匹配的作品列表和详情响应，只能由新的真实报告判断。`verified=1` 且无安全提示，才算这个低请求量闭环跑通；`candidate-only` 或 `blocked` 需如实保留，不继续补发请求来凑结果。

## 真实试跑记录

- `r8-homepage-20260924-222844-665-ea614e03`：一位作者、一个作品 `7662218043044416811` 通过主页作品列表和作品详情的双 ID 核对；2 次导航、0 次主动接口请求。首版清理逻辑自动关闭了作品页，用户无法做页面对照。该报告原样保留。
- `r8-homepage-20260924-223453-526-2f2e9b7b`：启动时没有已打开的抖音页，前置检查按旧规则阻断为 `NO_EXISTING_DOUYIN_TAB`；没有访问作者主页。该报告原样保留。
- `r8-homepage-20260924-224608-975-76d7461a`：扩展先打开抖音首页检查，再访问作者主页与一个作品页。报告为 `verified`：6 个主页可见候选，作品 `7662218043044416811` 的 `aweme_id`、`author.uid`、`author.sec_uid` 分别与已保存作者和自然加载的列表／详情响应匹配；共 3 次导航、0 次主动接口请求、约 16.3 秒。作品页已按用户现场反馈保留，弹窗显示 `verified`。Observer 另记 `RESPONSE_BODY_UNAVAILABLE`、`RESPONSE_TOO_LARGE` 和无关路径诊断；它们没有被当作目标作品证明。

这只证明单作者、单作品的低请求量闭环。自动关注增量、更多作者与作品、评论及回复、正式客户端任务调度与 SQLite 迁移仍需分别实施和验收；正式同步能力门保持关闭。
