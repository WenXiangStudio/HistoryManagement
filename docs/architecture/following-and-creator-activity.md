# 关注清单与博主状态：当前实现

视频模块当前扩展见[视频日期查找、本地材料与云端摘要](video-content-processing.md)：原有博主与分组规则保留；本地摘要质量门关闭，云端真实验收待用户配置。
关注连接器0.8.5。主要模块为 `FollowingSyncService`、`FollowingPlanStore`、`CreatorActivityService`、`CreatorActivityIntegrityStore`、`creator-activity-runner.js` 和共享规则。界面与主进程共同使用频率、近期状态和刷新范围的计算函数。

APP 0.1.14 新增独立的[单视频基础信息入口](video-information-first-step.md)，复用现有账号和作者身份，分别保存作品信息，不改变本页的主页状态与频率计算规则。

## 账号、目录与动作

关注清单完整分页读取、逐页入库；基础资料缺失项形成独立待办，每批最多20位。博主状态支持单卡、勾选、分组和恢复原剩余名单。数据按账号累计，主页secUid去重，原记录ID、星标、批注、历史捕获和失败证据保持稳定。部分或空结果不得删除已有博主。

资料库只挂载选中的区域。刷新范围根据当前账号完整目录生成，不受搜索限制；勾选只作用于当前可见作者。关注同步的点击到头像可用确认通过预加载本机头像完成，不依赖全部卡片挂载。

## 频率、近期状态和手动权重

`creatorRefreshTier`将未取整的个人平均间隔分成≤7天、>7～14天、>14～30天、>30天四档。`creatorAutomaticTier`和`creatorRefreshSchedule`共同使用成功核验的最近发布时间进一步判断：

1. 有效发布时间距离最近成功核验超过30天：极低频，优先于平均间隔；恰好30天仍在近期范围。
2. 平均间隔≤7天：核验时距最近发布≤7天为高频，>7～30天为中频；近期依据不足为待确认。
3. 其余使用平均间隔结果。缺少可用间隔显示待确认，不把缺失值当0。

建议检查间隔1／7／14／30天，以北京时间日期计算到期提示。核验结果不会因跨日、跨周或窗口重新打开而自动降级。主动分组更新包含未到期作者，没有后台定时采集。

`CreatorPriorityStore`按账号+主页保存手动模式、明确目标等级和revision。加/降权互斥，从开启当时的自动等级升降一级，最高高频、最低极低频；待确认加权进中频、降权进极低频。保存的目标不被后续自动分类覆盖，关闭恢复最新自动结果。异常隔离优先于正常分组。

`CreatorNameProvider`按账号和主页/UID关联名字，不以昵称文本匹配。昵称优先级为手动紫色→最近核验七天无更新红色`#B42318`→默认色。七天无更新的日期标签与日期为`#FF8247`。本周计数仍保留，但不决定昵称颜色。

## 数据字段与平均间隔

主页作品总数来自目标页可见且稳定的“作品”计数。最近公开发布时间来自可信作者列表，不使用检查时间替代。`weeklyUpdateCount`与周内`latestPublishedAt`仍按北京时间周一至下周一不含末端统计；日期展示和七天判断使用独立的跨周基线时间及`recentActivity`。

`creatorPublicationInterval`只接纳账号和作者双ID匹配、公开状态明确、日期有效的记录。作品ID去重，时间排序，n条记录产生n-1个相邻间隔；同一时刻不同作品可产生0间隔。内部保留秒级精度，卡片最后四舍五入显示整数小时，分类不使用显示取整值。

当前作品集合采用最后一份无错误、连续读至列表末尾且去重公开数与主页计数一致的完整列表，再合并较新有效观察；明确变为非公开的记录不再参与当前公开间隔。原始历史快照保留。部分、失败及异常隔离快照不会覆盖有效基线，失败/部分来源不更新当前间隔。

当前账号的平均间隔是各可计算作者个人平均的等权平均；不能混合所有作者的作品间隔，也不能给记录不足者填0。采集覆盖范围与发布频率是不同指标。

## 异常检测、隔离与补齐

`creator_activity_reviews`引用不可变源快照及旧基线，保存总数变化、实际新公开ID数、交集数、普通作品衔接点和原因。

- 普通刷新遇到总数净增≥10，读取首屏后进入异常，不继续常规分页。
- 净增超过实际取得的新ID数，或未衔接旧基线的最新非置顶作品且没有完整计数一致的列表，也进入异常。旧置顶记录单独出现不证明衔接。
- 异常结果保存原始证据，可展示新主页数；累计时间线与每次前端数按观察更新，但连续性核验仍保留未解决异常的旧锚点，异常观测不冒充已通过的正常间隔来源。新增数量按 `M < 发布时间 ≤ X` 统计，旧置顶/补充不混入；累计作品和失效标签见[时间基线规范](creator-publication-time-baseline-2026-10-13.md)。普通批次继续其他作者，异常作者进入单独队列。
- 高频／中频／低频／全量刷新均排除待处理异常。右侧异常入口与四档切换分离，分组内提供“一键核验并补齐”和单作者“核验并补齐”。批量范围使用当前账号完整异常分组，不受搜索影响；沿用单作者连续补齐规则和原批次等待策略，成功解除异常，未完整衔接的仍保留异常及剩余任务，可取消与继续。
- 补齐禁止未更新跳过，连续翻页到旧衔接点并解释净增数，或取得计数一致的完整公开列表，同时通过身份、来源、可见性和覆盖复核，才解除异常并提升新基线。
- 普通读取最多10页；显式补齐最多200页、读取循环90秒。失败、取消、断线及重启保留旧基线和异常，恢复任务保留repair语义。

主页总数不是本地已下载记录数。核验638→680的变化需要解释42个新作品ID，不要求旧本地存有全部638条。异常规则用于后续读取，未回溯重写历史快照。

## 浏览器读取、节奏与故障

每位作者使用独立临时页。准备过程核对目标主页、DOM可读状态和原生作品计数；interactive且内容可读时不等待所有资源complete。计数须稳定500毫秒，准备最多12秒。短暂执行上下文替换仅重做只读准备检查；非预期debugger detach立即拒绝等待命令并报告。

首位作者核验当前登录账号，优先复用本轮原生账号响应；没有观察到时允许一次明确账号GET。作品第一页可复用已观察响应，其余必要读取使用明确GET。身份/来源错误、已观察拒绝和验证码不被当作缺少响应重试。

网络监听只保留小投影，单响应8MiB、总缓存32MiB、每位最多24个匹配请求。原生第一页有600毫秒到达宽限、1500毫秒就绪和2000毫秒内容读取界限。后端复核作者UID/secUid、作品ID、公开状态、游标连续性、去重和日期覆盖。

普通批量中，总数相同优先比较原生最新作品ID和发布时间。无可用原生列表时仍允许用户已接受的仅计数跳过，独立保存轻量检查及关联快照；这不能证明新增与删除没有相互抵消，也不等于完整历史核验。

每批33位，作者间等待3～8秒、批间3～5分钟。结果保存确认后立即停止观察、释放调试连接并关闭该临时页，再进行本地等待。取消/恢复保留原剩余名单及未完成等待，不重新按当前分组挑人。

首次失败冻结有界日志，停止后续业务，保留故障页，分别尝试扩展缓存和APP诊断保存。允许诊断frozen→complete，不覆盖首次完整证据。诊断不保存Cookie、headers、完整query、表达式或异常原文。HTTP拒绝、验证码和断线均停止；不会自动处理验证或重试业务请求。

`creator_activity_observations`另存成功、计数回退及失败时序，可通过`scripts/export-creator-activity-observations.mjs`只读导出。阶段耗时与点击到资料及头像可用的全程指标分开记录。

## 数据库、图表与外部同步

`CreatorDatabaseStore`按账号投影自动五列，允许增加自定义列及修改表头、顺序、宽度、对齐。自定义值以revision事务防止过期写入，编辑不被轮询覆盖。筛选按账号持久化；数字和日期缺失值须显式筛选为空。

表格虚拟化保留可变行高和编辑行；已访问的数据库/图表页保留状态，隐藏时停止效果与轮询。账号切换隔离缓存，晚到请求不会覆盖新账号视图。

飞书使用同一投影做APP→飞书同步，保留原自动同步配置，详见[飞书实现](feishu-creator-database.md)。正式作品／评论R8能力门仍关闭，历史验收见[归档索引](../handoff/archive/README.md)，日常入口见[当前交接](../handoff/README.md)。
